# Academic Demonstration Guide

## Short presentation outline

1. Introduce TruthScan as an article-classification software project, not an oracle of truth.
2. Show the inspected architecture: frontend, FastAPI routes, preprocessing, ensemble, and artifact verification boundary.
3. Show the audit trail and explain why provenance and licensing gates remain active.
4. Show the isolated Track B mockup only as a synthetic contract/UI demonstration.
5. Close with the distinction between academic demonstration and public release approval.

## Safe demonstration sequence

- Use source views, existing documentation, static diagrams, and prior audit reports.
- If showing the live application, use only a separately approved environment and do not imply that its historical artifacts are authenticated.
- Open `UI_MOCKUP.html` as a static mockup. Point out `SYNTHETIC FIXTURE ONLY`, the disabled control, the synthetic evidence label, and the non-authoritative disclaimer.
- Explain the three Track B semantic outcomes: `SUPPORTED`, `REFUTED`, and `INSUFFICIENT_EVIDENCE`. Do not translate them to Fake/Real.
- Use the recorded synthetic test results only as evidence of contract behavior within that isolated scope.

## Do not present as production-ready

- Do not call the Track B prototype a working fact checker or evidence-retrieval service.
- Do not claim the historical model bundle is authenticated or reproducible.
- Do not claim the dataset is licensed for public hosting, commercial use, model distribution, or redistribution.
- Do not present README accuracy as a current independently verified benchmark.
- Do not claim that a healthy server, HTTPS URL, checksum, or public repository proves release trust.
- Do not suggest that synthetic tests authorize real-data training or deployment.

## Suggested answers

**What does the model prove?** It produces a learned Fake/Real signal for text resembling its training distribution; it does not verify claims against live sources.

**Is the data cleared?** No. Prior provenance and rights audits retain the blocker; public availability and local hashes are not sufficient.

**Is the security work complete?** Source-level and synthetic fail-closed safeguards exist, but real trust roots, authenticated evidence, and deployment review remain outstanding.

**Can the claim demo be deployed?** No. It is an isolated synthetic-only mockup with no production route.

**What is next?** Obtain owner decisions and authoritative rights/provenance/environment evidence, then run the existing gates without weakening them.
